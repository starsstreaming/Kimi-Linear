## 数学与数值解释

1. **Householder（镜像反射）表述过强。** 单位key下，`I-βkkᵀ`只有在β=2时是标准Householder反射；β=1是去掉key方向分量的投影，0<β<1是收缩。`kkᵀ`自身不是反射矩阵。原始模型β由sigmoid给出，不默认等于2。
2. **float32溢出阈值算错。** float32最大有限值约3.40×10³⁸，其自然对数约88.72。α=0.90、C=512时，`1/α^C≈exp(53.94)`，并未达到float32表示上限；C=256也不是必然溢出。单纯倒数表示溢出的首个整数块长，α=0.90为843，α=0.99为8828。精度丢失、半精度范围和其他中间运算可能更早出问题，不能与表示溢出混为一谈。[可重算结果](../results/verified-cpu.json)
3. **衰减倒数不是唯一风险。** 还要检查归一化、累加误差、下三角求解的条件、数据类型与梯度。数值等价性测试必须注明输入分布与容差，不能一句话推广到全部输入。
4. **简化变体不是完整模型。** “标量门+直接累加”只能叫Mamba2风格关联记忆对照，不能当作完整Mamba2复现；GLA/GDN的命名也应保留这个层级限定。

## 架构与效率口径

| 原资料容易造成的误读 | 应采用的口径 |
|---|---|
| 所有层严格循环3:1 | 发布模型27层中20 KDA、7 MLA，末层补MLA |
| 完整模型预填充从二次变成线性 | 纯KDA部分近线性；混合模型仍含MLA二次项 |
| KV−75%就是总显存−75% | token相关KV与总显存是不同指标 |
| 48层×32头×128维的普通KV计算代表官方MLA | 这是示意性MHA缓存模型；MLA潜变量缓存要按配置另算 |
| 6.3×是所有单请求延迟提升 | 论文§6.3：1M时batch=1约2.3×，扩大batch后约6.3×吞吐 |
| 4×访存比是所有系统的速度上限 | 只在特定缓存与带宽模型下成立；还有计算、权重、调度等成本 |
| FLOPs（浮点运算次数）或CPU计时验证GPU速度 | 只能支持相应算法计数或该CPU实现的结果 |
| 小规模结果解释全部大模型差距 | 玩具任务仅检验该任务该配置；不足以确认规模是唯一原因 |

论文对比是给定训练和评测条件下的整体表现，“首次”“全面超越”按作者宣称引用。不得改成所有模型、所有任务与每一个基准上的定理。[论文§5–6](https://arxiv.org/html/2510.26692v1#S5)

## 历史实验结果与本仓库结果

HTML中的MQAR准确率、CPU DPLR倍率、FLOPs图和门控学习曲线是**原资料报告值**。没有相应完整脚本、日志与JSON，就不能按图上的数字重建真实训练轨迹，也不能说已在当前机器复现。原文“4变体×3长度×3种子共34次”与乘积36不一致，应由原始日志解释，不擅自补两次结果。

本仓库仅新增120组算子等价性运行与8项行为测试。门控曲线、训练、GPU效率、48B基准与SFT/RL都未重新运行。测试修复先经历缺少实现模块的失败，再加入完整参考实现；后续通过的命令和结果记录在[结果说明](../results/README.md)。
