# MQAR复现协议与缺失项

MQAR（Multi-Query Associative Recall，多查询关联召回）要求模型记住若干key→value配对，再回答多个key查询。它用于检验有限状态在干扰和距离下保存关联的能力。

## 原资料报告的设置

以下从用户HTML转录，不表示本仓库已经运行：

| 项目 | 原资料设置 |
|---|---|
| 网络 | 2层，模型维度64，2头 |
| 任务 | T=64/4对，T=128/8对，T=256/16对 |
| 门控/更新对照 | 通道/标量遗忘门 × Delta/直接累加 |
| 训练 | 1200步，batch32，AdamW，学习率3e-3，OneCycle |
| 种子 | 3个；具体值未给出 |
| 数值处理 | float32训练；log门截断[-1,0] |
| 原报告结果 | 玩具规模下GDN≈KDA；通道门学到不同遗忘率 |
| 扩展任务 | 同key先写v1再写v2，查询最新值 |

## 补齐后才能重新运行的契约

| 必须明确的项 | 原因 |
|---|---|
| 完整模型：投影、卷积、激活、输出门、归一化、FFN、残差 | 避免把不同网络归因到遗忘门 |
| key/value词表、重复key、填充、查询位置和目标对齐 | 避免目标泄漏或偏差任务 |
| 数据生成种子与模型初始化种子 | 分开控制数据与初始化随机性 |
| 训练数据与固定验证集独立 | 防止把训练记忆当泛化召回 |
| 分类器看到当前查询token还是预测下一个token | 确认不是意外改成不同任务 |
| 优化器完整参数、调度曲线、梯度裁剪与数值门参数化 | 让训练可重复且比较公平 |
| 定期验证频率、最终/最佳模型的选择规则 | 避免挑峰值夸大结果 |
| 每步loss、验证准确率、非有限值和失败记录 | 为图中每个点提供可查证数据 |

原资料的“非有限损失跳过”不作为新实验的默认策略：一旦出现NaN/Inf，记录种子和步数并显式失败，再定位根因。不能静默跳过后继续报告成功。

## 独立重实现时的对照设计

1. 固定网络与训练预算，只改变门的粒度和是否用Delta更新；门粒度改变会带来参数量差异，应报告。
2. 至少运行3个固定种子，验证数据一致；若使用0/1/2，明确这是新实验选择，不是恢复的历史种子。
3. 报告均值、标准差、每个种子结果和失败数，主指标采用预先定义的最终验证准确率；最佳准确率作为辅助指标。
4. 保存全部曲线与门的分布，避免只提供漂亮截图；检查门参数的初始化与长度范围。
5. 同时改变长度和键值对数量时，报告的是联合难度变化。若要归因“长距离”，另固定配对数量只改变距离。
6. 覆盖任务是资料作者的加餐，不是论文原任务；作为独立实验命名，不能标为论文Figure 4复现。

## 接受与解释结果

先确认算子输出和梯度通过R1，再分析训练差异。若小任务上所有模型都接近满分，结论是该配置缺乏区分度；若KDA并未优于GDN，如实保留。可研究容量、难度和训练预算，但不能为了符合论文排序事后筛种子或改变主指标。
